# 10-damage-attribution

_From the PDB research workflow (2026-08-20)._

**Verdict:** RECOMMEND design (c): a scoped identity shim plus award redirection — not pure (a) impersonation and not pure (b) post-hoc re-attribution. Pure impersonation cannot work because progression lives behind a second, unrelated singleton (UESGameInstance::InstancePointer->PlayerData @+0x1C0), which no pawn/controller lie can duplicate on the host. Pure post-hoc re-attribution cannot work because the kill-credit branch at 01558CFA and the damage-modifier decisions at 012D03E7/012D0711/012D1814 never execute at all for a client instigator, so there is no award to redirect. The working shape is: one scope hook on the damage funnel (012D0210) that sets a thread-local acting player from the EventInstigator it already receives at [rsp_entry+0x38]; two inert-by-default detours on UGameplayStatics::GetPlayerPawn (013F08B8) and GetPlayerController (013F08F0) that are the ONLY identity accessors in the game (everything else calls them); and redirect hooks on UGameplayLib::AddXP (05E209B8), UGameplayLib::ChangeCredits (05E21DF0), UPlayerData::OnKilledActor (018EE664), UInventory::AddItem (0153C8FC) and UMetaSaveData::IncDeathCount (05E04894). Add UHitpointComponent::SaveDamageDealtInFactionComponent (0155A060) as a pass-through ledger to get exact per-player damage shares for free. All recommended RVAs verified unique (exactly one function symbol each); 012D0210 has no symbol at all and must be carried by hand. Two findings materially change the picture from earlier research: the XP gate is per-FACTION (EFactions::Player), so co-op damage POOLS and shared kills DO qualify; and the loot gate is a distance test OR'd with the same pooled player-damage counter, so client kills already drop loot. The genuinely new bug is UESGameInstance::AIvsAIDamageFactor (+0x6D0) being applied to all client-dealt damage.

## Summary

== 0. HEADLINE ==

Every ES2 "who is the player?" accessor collapses into ONE engine function: `UGameplayStatics::GetPlayerController(UObject const*, int)` @ 013F08F0. Verified by disassembly: GetESPlayerPawn (013F0CC0) = GetPlayerController(ctx,0)->GetPawnOrSpectator() cast to AESPawn; GetESPlayerController (0150D280), GetESHUD (015576B8), GetPlayerPawn (013F08B8), IsPlayerController (012D2898) and GetPlayerControllerWithoutContext (013EFE78, which supplies UESGameInstance::InstancePointer as the world context) all tail into it. GetPlayerController itself walks `World(+0x1D8 OwningGameInstance)->LocalPlayers(+0x38/+0x40)` and returns `LocalPlayers[idx]->PlayerController(+0x30)`. On a listen server a remote client is a UNetConnection, NOT a ULocalPlayer, so index 0 is always the host and index 1..3 return null. That is the whole bug.

The SECOND, independent singleton is `UGameplayLib::GetPlayerData()` @ 0127398C = `UESGameInstance::InstancePointer(global @ RVA 09AC5E88)->PlayerData(+0x1C0)`. There is exactly one UPlayerData per process, so no amount of pawn/controller impersonation can make the host write into a client's save. This is the decisive reason the fix cannot be pure impersonation.

The GOOD news, verified at every step: the real actor identity is present as an explicit argument all the way down the damage/kill path. `AWeaponBase::DealInstantHitDamage` @ 014289AC gets it at 01428A85 from `AActor::GetInstigatorController()` (0142A190) and passes it as arg7 to ApplyESPointDamage; the funnel forwards it; UHealthComponent::TakeDamage receives it in r9; SaveDamageDealtInFactionComponent receives it in r8; UXPComponent::OwnerHealthDepleted receives it in r9. Nothing is lost — only the *comparisons* are wrong.

== 3. DESIGN EVALUATION AND RECOMMENDATION ==

(a) PURE IMPERSONATION — rejected. Three disqualifying facts:
  * It is *technically* cheap: one detour on 013F08F0 covers every ES2 identity accessor (and 013F08B8 for the pawn shortcut). Both are unique RVAs. Re-entrancy is manageable with a save/restore TLS.
  * But `GetPlayerData()` reads a DIFFERENT global (UESGameInstance::InstancePointer->PlayerData). No pawn/controller lie creates a second UPlayerData on the host. So AddXP, ChangeCredits, OnKilledActor, ProgressChallenge, IncDeathCount and UInventory::AddItem would all still hit the HOST's save — i.e. impersonation alone fixes nothing that matters and actively makes things worse (it would open the *host's* kill-credit branch for client kills).
  * Blast radius: 131 GetPlayerController callers + 88 GetPlayerPawn callers. Impersonating across the whole dynamic extent of a damage event means arbitrary code (BP death logic, sequences, saving, wanted-level manager) runs believing the client is the player.

(b) PURE POST-HOC RE-ATTRIBUTION — rejected as insufficient. For XP it works (the XP gate is faction-pooled, so the vanilla path DOES fire for client kills and you only need to redirect the award). But for kill credit it does not: the branch at 01558CFA never executes when the instigator is a client, so there is nothing to re-attribute. Same for the item-damage modifiers (012D1814) and AIvsAIDamageFactor (012D03E7..012D040A) — those are *input* decisions, not awards.

**RECOMMENDED: (c) SCOPED IDENTITY SHIM + AWARD REDIRECTION.** One outer scope hook establishes "player N is acting"; two inert-by-default accessor detours make the vanilla identity comparisons resolve to player N *only* inside that scope; award functions are redirected to the right UPlayerData (which means: message to client N).

  1. `ActingPlayer` is a **thread-local** (`__declspec(thread) CoopPlayer* g_acting`) with **save/restore stack discipline** — never set/clear. Damage re-enters itself (chain reactions, radial damage from a death explosion, DamageParts), so a naive clear would drop the outer scope.
  2. SCOPE HOOK: the funnel @ **012D0210**. Read EventInstigator at callee `[rsp_entry+0x38]` (equivalently `[rbp+0x980]` with the game's own rbp) and DamageCauser at `[rsp_entry+0x40]`. Map the controller through the mod's registry. If it is a remote co-op PC: `auto save=g_acting; g_acting=&playerN; original(...); g_acting=save;` — otherwise tail straight into the trampoline so the host path is bit-identical to vanilla. This single scope covers the funnel's own modifiers, all three component TakeDamage overrides, the OnHealthDepleted broadcast, UXPComponent, ULootDropComponent and the BP death logic, because they are all synchronous inside it.
  3. IDENTITY SHIM: detour `UGameplayStatics::GetPlayerPawn` @ **013F08B8** and `UGameplayStatics::GetPlayerController` @ **013F08F0**. Body: `if (g_acting && Index==0) return g_acting->pc (or ->pc->GetPawnOrSpectator());` else trampoline. Because g_acting is null outside a client-instigated damage event, HUD, input, sequences and menus are untouched. If a HUD path *does* run while active, GetESHUD(clientPC) returns null (MyHUD is null on a non-local PC) and every ES2 HUD site null-checks — that is the desired "the host does not see the client's floating numbers" behaviour, not a crash.
  4. AWARD REDIRECTION (mandatory in every design): detour `UGameplayLib::AddXP` @ **05E209B8** — if g_acting is a remote player, capture xmm0, skip the original, and send {playerId, xp} to that client, which calls the same RVA locally. Same shape for `UGameplayLib::ChangeCredits` @ **05E21DF0**, `UPlayerData::OnKilledActor` @ **018EE664**, `UInventory::AddItem` @ **0153C8FC** and `UMetaSaveData::IncDeathCount` @ **05E04894**.
  5. LEDGER (for proportional splitting, optional but cheap): detour `UHitpointComponent::SaveDamageDealtInFactionComponent` @ **0155A060** as a pass-through observer. It hands you (victim component -> Owner) + exact absorbed damage + the real AController* on every damage event, per hitpoint component, already summed the same way GetTotalMaxHitpoints sums. Keep your own `TMap<AActor*, float[4]>` and you never have to walk UE's TMap internals.
  6. LOOT PROXIMITY: while g_acting is set, GetPlayerPawn(0) at 016CCECD returns the client's pawn, so the distance test uses the right ship automatically. Belt-and-braces alternative: clear `ULootDropComponent::bOnlyDropLootWhenPlayerIsCloseOrWhenDamagedByPlayer` (+0xD9) on spawn. Note the OR-clause already saves most cases (see corrections).
  7. LOOT COLLECTION is a separate scope, not inside the funnel: hook `APickupBase::OnCollect_Implementation` @ **016B720C** (rdx = the collecting AActor*) and set g_acting from it before calling the original; then the AddItem redirect in step 4 sends the item to the right player.

Why this beats a global impersonation: the shim is a no-op 99.9% of the time, the scope is one function with a known ABI, and the award redirect is the part that actually has to exist regardless.

ALTERNATIVE, if you want zero global detours: patch the 5-byte `E8 rel32` at each of the 24 verified call sites to your own `GetPlayerPawnCtx/GetPlayerControllerCtx`. All 24 were byte-verified (first byte 0xE8, correct rel32 target). This is surgical and has literally no effect on HUD/menu callers. Its one weakness: MSVC PGO cold chunks in 0x2880000–0x2B40000 contain *additional* copies of some of these comparisons (e.g. 02B2557A and 02B25729 are cold parts of UXPComponent::OwnerHealthDepleted; 02889C94 calls GetPlayerController from the funnel/CheckForItemDamageChangingEffects cold region), so a hot-path-only patch set will silently miss branches. If you go this route you must scan the *whole* .text, not just the hot function bodies.

== 4. HOW TO IDENTIFY THE KILLER (concrete field reads, host side) ==

Best to worst, all verified:
  1. **AController* EventInstigator**, delivered as a parameter — funnel `[rsp_entry+0x38]`, UHealthComponent::TakeDamage `r9`, SaveDamageDealtInFactionComponent `r8`, UXPComponent::OwnerHealthDepleted `r9`. Map directly through the mod's APlayerController*->id registry. This is the authoritative answer.
  2. **UHealthComponent::LastDamageCauser** — `*(AActor**)((u8*)healthComp + 0x4F8)`, written unconditionally at 0155880F. Then `causer->Instigator (AActor+0x1A0) -> Controller (APawn+0x2D8)`.
  3. **APawn::LastHitBy** — `*(AController**)((u8*)victimPawn + 0x2D0)`. Verified written by APawn::TakeDamage @0142B180 (at 0142B1F8, via FObjectPtr::operator=) when the returned damage != 0 and the instigator != the victim's own Controller. Only exists for APawn victims.
  4. **UFactionComponent::AggroMap** — per-actor cumulative hitpoints, `(u8*)factionComp + 0x160`, TMap<TWeakObjectPtr<AActor>,float>: Elements.Data ptr @+0x00 / Num @+0x08, element stride 20 = {int32 ObjectIndex@0, int32 ObjectSerial@4, float Damage@8, int32 HashNextId@0xC, int32 HashIndex@0x10}; AllocationFlags TBitArray @+0x10 (inline uint32[4] @+0x10, NumBits @+0x28); FirstFreeIndex @+0x40, NumFreeIndices @+0x44. Skip index i unless bit i of AllocationFlags is set.
  5. **FactionEntries[EFactions::Player].HitpointsDealt** — `*(float*)(*(u8**)((u8*)factionComp + 0x150) + 0xC)`. Pooled across both co-op ships; this is what the XP and loot gates read.
  6. **AESPawn::PrioritizedTargetLists.AggroList** — TArray<AActor*> at AESPawn+0xF70; every actor that crossed HitpointRatioNeededToTurnHostile.
  7. Your own ledger from the 0155A060 hook — the only source that gives you an exact per-player split with no TMap walking.

Practical rule at the award point: prefer the passed EventInstigator; fall back to LastHitBy / LastDamageCauser->Instigator->Controller; use your own ledger (or AggroMap) to decide the *split* when both players contributed.

== 5. FAILURE MODES TO GUARD AGAINST ==
* Re-entrancy: the funnel calls itself indirectly (radial damage from an explosion spawned by a death, DamageParts, chain reactions). Save/restore g_acting; never clear.
* Never hook via a shared RVA. Example of a real trap in this area: `ULootCollectComponent::TickComponent` @ 0192E204 is ICF-folded across 11 functions; `UHitpointComponent::TakeDamage` base @ 012386C0 is the universal empty stub. All RVAs recommended here were checked and are unique (012D0210 has no symbol at all — it is a static, hence not ICF-shared, but the mod must carry it as a hand-added address and the PE-timestamp guard becomes load-bearing).
* Stale pointer capture: while the shim is active, any code that *stores* the returned pawn/controller beyond the scope now holds the client's. ULootCollectComponent::OnBeginOverlapCollect pushes into a TArray; APickupBase::OnCollect removes from AESPlayerController+0x9E0. Keep windows tight and audit writes.
* Do not shim during spawn/possession: `AESGameModeBase::SpawnDefaultPawnAtTransform_Implementation` @05DEEF02 calls GetESPlayerController. g_acting must be null there.
* Host-side saves: `UMetaSaveData::SaveToDisk` @05E16674 fires on player death (01558CE5). A client death currently triggers it on the host's save — block it before you add impersonation, not after.
* AddXP/ChangeCredits are also reachable from Blueprint via exec stubs (05B87ED4 / 05B89C6B), which route through the same RVAs — one hook covers both, but it also means mission-reward XP will hit your redirect. Decide deliberately whether mission rewards go to the causing player or to everyone (AddNonItemRewards @05E71518 is the split point).
* Unreliable transport: award messages must be idempotent + sequenced, or a duplicated packet double-awards XP.
* The client applies AddXP locally against its own UPlayerData; make sure the client is not ALSO running its own copy of the kill (the existing funnel block on clients already prevents that).

## Hook plan

- **ES_ApplyDamage_Internal (unnamed damage funnel) — SCOPE HOOK** @ `012D0210` [host] — Establish the thread-local 'acting player' for the entire dynamic extent of one damage event: the funnel's own modifiers, Shield/Armor/Health TakeDamage, the OnHealthDepleted broadcast, UXPComponent, ULootDropComponent and the Blueprint death logic all run synchronously inside this call.
  - behaviour: Around. On entry read AController* EventInstigator from callee [rsp_entry+0x38] (= [rbp+0x980] in the game's own frame) and AActor* DamageCauser from [rsp_entry+0x40]. Look the controller up in the mod's APlayerController*->id registry. If it is NOT a remote co-op controller, tail into the trampoline unchanged so the host path is bit-identical to vanilla. If it is: `auto* saved = g_acting; g_acting = &player[N]; trampoline(...); g_acting = saved;`. Declare the trampoline with all 15 args so the stack is right; do NOT touch the sret slot.
  - risk: Medium. No symbol exists at this RVA, so gen_sdk must carry it by hand and the PE-timestamp guard is load-bearing — a patch moves it silently. It is verifiably a real entry (16-byte aligned, full MSVC prologue, `lea rbp,[rax-0x948]; sub rsp,0xA08`) and verifiably the only funnel (5 call sites). The mod already hooks this address to block client-side damage: use ONE hook object with a role branch, never two detours on one address. Save/restore g_acting rather than clearing — the funnel re-enters itself via chain reactions and death explosions.
- **UGameplayStatics::GetPlayerPawn — IDENTITY SHIM** @ `013F08B8` [host] — Make the ~10 `== GetPlayerPawn(0)` comparisons on the damage/kill/loot path resolve to the acting client, without disturbing the other 78 callers.
  - behaviour: Replace conditionally. `if (g_acting && PlayerIndex == 0) return g_acting->pc ? g_acting->pc->GetPawnOrSpectator() : nullptr;` else tail into the trampoline. GetPawnOrSpectator is 013F08D8 (unique) — or just read APlayerController::Pawn if you prefer no call. g_acting is null everywhere except inside a client-instigated damage/collect scope, so HUD, input, sequences, spawning and menus never see the lie.
  - risk: Low-medium. Unique RVA, 8-instruction body, trivially trampolined. The residual risk is code that CAPTURES the returned pawn beyond the scope (ULootCollectComponent::OnBeginOverlapCollect pushes into a TArray; APickupBase::OnCollect edits AESPlayerController+0x9E0). Keep the scope tight and audit stores. Called at high frequency — keep the fast path to a TLS load and a compare.
- **UGameplayStatics::GetPlayerController — IDENTITY SHIM** @ `013F08F0` [host] — Same, for the controller-identity gates: the kill-credit gate (01558CFA), the funnel's AIvsAIDamageFactor and player-item gates (012D03FB / 012D04E8 / 012D0711), UGameplayLib::IsPlayerController (which feeds AWeaponBase::CheckForItemDamageChangingEffects and the XP fallback), the pickup path and ULootCollectComponent.
  - behaviour: Replace conditionally. `if (g_acting && PlayerIndex == 0) return g_acting->pc;` else tail into the trampoline. Hooking this ONE function also covers GetESPlayerPawn, GetESPlayerController, GetESHUD, GetPlayerControllerWithoutContext and GetPlayerPawn, because every one of them calls it — verified by disassembly of all five.
  - risk: Medium. 131 callers, so the inert-by-default contract is what keeps this safe: never leave g_acting set across a frame boundary or a ProcessEvent that can yield. While active, GetESHUD returns null (a remote PC has MyHUD==null) — every ES2 HUD site null-checks, so this manifests as 'the host stops seeing the client's damage/XP numbers', which is correct behaviour, not a bug. Must NOT be active during pawn spawn/possession (AESGameModeBase::SpawnDefaultPawnAtTransform_Implementation @05DEEF02 calls GetESPlayerController).
- **UGameplayLib::AddXP — AWARD REDIRECT** @ `05E209B8` [host] — Send XP to the player who earned it instead of writing the host's UPlayerData. Covers both the kill path and Blueprint/mission callers, because execAddXP and UMissionLib::AddNonItemRewards both route through this RVA.
  - behaviour: Replace conditionally. ABI: xmm0=float XP, dl=bHideLevelUpAnimation, r8b=bIgnoreLevelCap, xmm3=float LevelUpAnimationDelay, return bool in al. If g_acting names a remote player: capture XP, skip the original, enqueue {seq, playerId, xp, flags} on the reliable host->client channel, return true. Otherwise trampoline.   - risk: Low. Unique, 16-byte body, only 3 callers. Two things to decide deliberately: (a) mission rewards will now be redirected too — you probably want those broadcast to everyone rather than to the last damager; (b) the level-delta scaling that produced this XP value used the HOST's UPlayerData::Level(+0x128) versus AESPawn::NPCLevel(+0x1038). If you care, recompute the multiplier client-side from the client's own level (1.0 / 0.75 / 0.5 / 0.25 / 0 for a delta of <=0 / 1 / 2 / 3 / >=4) and send the unscaled XP plus the victim's NPCLevel.
- **UHitpointComponent::SaveDamageDealtInFactionComponent — LEDGER** @ `0155A060` [host] — Build an exact per-victim, per-player damage ledger with zero TMap reverse-engineering, so kills can be split proportionally and 'who killed this' has a second, independent answer.
  - behaviour: Observe (call the trampoline first, then record). ABI: rcx=UHitpointComponent* this, xmm1=float Damage, r8=AController* Instigator. Read victim = this->OwnerPrivate (+0x90); map Instigator through the registry; accumulate `ledger[victim][playerId] += Damage`. It is invoked once per damaged component (shield, armor, health) with the absorbed amount, which sums exactly the way GetTotalMaxHitpoints sums — so your ratios match the game's own.   - risk: Low. Unique RVA, 3 call sites (Shield 012CF315, Armor 01557082, Health 01558B67), tiny body, no side effects to preserve. - **UXPComponent::OwnerHealthDepleted — SPLIT POINT** @ `019423AC` [host] — The single, well-typed place where a kill turns into XP, with the real AController* in hand. Use it to decide the split before the vanilla award runs.
