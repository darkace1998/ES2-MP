# 08-steam-p2p-verified

_From the PDB research workflow (2026-08-20)._

**Verdict:** The doc is ~85% accurate on mechanics but WRONG on its two load-bearing conclusions. (1) "No lobby/session needed" is false — the accept path is gated on GetNumSessions()>0 upstream of Finalize; a Steam-P2P host built to the doc's recipe would listen forever and never accept a peer, with no log line. (2) Three ABI entries invert sret/this, which per the project's own hard-won rule is a guaranteed crash. Additionally the recommended runtime probe (FSteamSharedModule::IsAvailable) does not test what the doc says it tests. With the corrections below the Steam path is fully specifiable and ~90% of it is verifiable on one machine with one Steam account.

## Summary

Adversarial re-verification of docs/research/06-steam-p2p-4player.md against sdk/symbols.tsv, tools/pdb_types.py and tools/disasm.py.

UNIQUENESS: all 17 claimed function RVAs resolve to exactly one `function` symbol (`grep -c '^<RVA>\t' sdk/symbols.tsv` == 1). The single exception is `09B2A610`, which has NO symbol at all — it is a derived data address (still correct; see corrections).

THE HEADLINE CLAIM IS FALSE. The doc's section "Does the host need a lobby/session? — NO (verified)" only inspected the *consumer* (`FOnlineAsyncEventSteamConnectionRequest::Finalize` 052A6698, which genuinely has no session check). The *producer* — `FOnlineAsyncTaskManagerSteam::OnP2PSessionRequest` (052B53C4), the real `P2PSessionRequest_t` client callback — gates on `SteamSubsystem->GetSessionInterface()` being valid AND `IOnlineSession::GetNumSessions() > 0` (vtable slot 137 = [vt+0x448]) before it will even allocate/queue the event. With ES2 never creating a session (confirmed: zero session calls in sdk/es2_functions.txt), `FOnlineSessionSteam::Sessions.Num()` is 0 and every incoming Steam P2P request is silently dropped. This is the single most important actionable finding: the mod MUST make GetNumSessions() > 0 on the host.

Seven further corrections follow (inverted sret/this ABI on three functions, `bUsingSteamNetworking` being plugin-gated not unconditional, `FSteamSharedModule::IsAvailable` not being a SteamAPI health check, Finalize running on the GAME thread not the online thread, an omitted null-check in AcceptP2PConnection, asymmetric client/host behaviour when the STEAM subsystem is null, and conditional bIsValid in SetIp). Everything else in the doc that I checked disassembles exactly as claimed.

For Part 2 I derived a complete no-second-account test path: 10 purely local runtime checks with exact functions/globals/ABI, a proven way to read the local SteamID64 in three independent ways, the exact health flag for "did SteamAPI initialise" (`FOnlineSubsystemSteam+0xD8`), and the exact place to read "is STEAM the default socket subsystem" (`FSocketSubsystemModule+0x8`, module pointer at RVA 09CC52C0).
